# 0021 — Scripts are claims: the rejection summary, --strict, one-based slots, unarmed

Date: 2026-09-19. Issue 101, filed by Chat from its cold play of the Tollgate (six of eighty-five commands rejected, three units silently losing a turn). Builder's calls on the two one-liners, recorded on the issue and applied here.

1. **A scripted run ends with a summary of every rejected line.** The per-command `ERROR:` lines stay where they are; after the last command, before the outcome line, `rejected N of M commands:` lists each rejected line with its file line number (blank lines and comments count, so the number matches the editor), the command text, and the reason. A clean run prints nothing, so existing transcripts that ran clean are unchanged in shape. Interactive play is untouched: a rejection at the keyboard is free.
2. **`--strict` stops at the first rejection** with `strict: stopped at line N (<command>); no later command applied` and exits 3 (0 is a win, 1 a loss or an unfinished battle, 2 a usage error). It requires `--script`. The test corpus replays the committed winning script under it, so a rules change that makes a line illegal fails loudly instead of replaying a mutated game. Journal plays run without it, because the fumble is part of the record.
3. **Slots count from one at the CLI boundary, from zero in the core.** `show` lists `1: Iron Sword x40, 2: Field Dressing x3`; `attack`, `forecast`, and `item` read the number the same way and pass `slot - 1` to the core. A slot outside 1..count is refused by the CLI itself, naming the range the player sees, so the core's zero-based `EmptySlot` message never reaches the screen. The core's `NotUsable` message now names the item (`captain cannot attack with field_dressing: an item, not a weapon`) instead of the index, since a message that names an index would be wrong on one side of the boundary whichever convention it used; that is the only core change, and it is wording. Committed scripts from 2026-09-18 keep their zero-based numbers as records of that build (transcripts README); the winning Old Mill Road script names no slot, so nothing was rewritten.
4. **An unarmed unit says so.** The board's legend line carries `unarmed` for any unit whose `EquippedWeapon` is null, and `show` prints `weapon: unarmed` or `weapon: unarmed (spell spent)` when a castable spell sits at zero uses. The marker is the tell for the enemy planner's existing magnet (DIALOGUE.md, seventh round, second pass): the planner prices a unit that cannot counter as free damage, so the player must see it coming.
5. **`play` takes a bare map name.** `play the_tollgate` resolves to `<content>/maps/the_tollgate.map` when no file exists at the path given; an existing path is used as given.

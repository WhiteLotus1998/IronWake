# 0122 — The text pass, slice 2f: `help`, the verdicts and the campaign screen

Date: 2026-10-01. Issue #615, the rest of item 1. Follows 0113 and 0116 to 0120. The Builder implementing what the Table already agreed (round 184: on-screen text uses display names, scripts keep ids). Chat can argue the wording on the PR. With this slice #615 is done.

## What changed

- **`help`** in `play` and between maps: headings and every description in sentence case (`Commands:`, `move <unit> <x,y>        Move a unit to a tile in its reach`). The command column stays lower case, because it is what a player types. Rule text that speaks of "a unit ... its turn" stays generic, as 0116 left it.
- **The verdicts.** `Battle won: seize`, `Battle lost: the captain is dead`, `Battle ongoing at turn 1, player phase`, the mid-battle `Battle won: ...; only recall is left`, `Escaped: Rook, Alder Fenn; left behind: none; fell: Pell`, `Certification: Alder Fenn earned Outrider`, `Strict: stopped at line ...`. The outcome reason keeps its case; it names units through `UnitNames.Named`, the id-to-name pass without sentence case, for a clause set inside a line.
- **A role is not a unit.** `UnitNames.Message` reads a word after `the`, `a` or `an` as a role, not an id, so `the captain is dead` no longer reads `the Alder Fenn is dead` (a slip in 0120's refusals) and `captain is the captain and leads every map` reads `Alder Fenn is the captain and leads every map`.
- **The campaign screen.** `UnitNames.Of(CampaignRecord, GameContent)` names every roster unit and every fallen one from the cast file, with pronouns. Refusals, accepted actions (`Wren buys Iron Sword for 400; ...`), a trial's result, the won line's fallen, the lost line, the deployment line, the roster and its fallen, and `classes` read by name in sentence case. The roster, as the console and `CampaignClient.ScreenLines` print it, adds the id a command types where it differs (`Alder Fenn (captain): Cadet L1, EXP 0; ...`); the Godot screen's clickable rows keep the bare name. Headings read `Roster:`, `Shop:`, `Classes:`, `Keep:`, `Deploys to ...`, `-- Before map 1 of 8: ... --`, `Map 2 of 2: ...`, `Campaign won: ...`. `show`'s stats read `HP 20  Str 7 ...` and `Ranks:` as the battle's `show` does. The shop keeps the ids `buy` takes.
- **The client's** campaign log and refusal status go through the same `CampaignSession.Text`, so the campaign parity gate still compares like with like. The art menu's greyed row names units in its reason fragment.
- **Transcripts.** The 30 that tests compare and that print a changed line were regenerated by running them through the tests' own commands; the diff is wording only.

# 0120 — The text pass, slice 2e: refusals by name, in sentence case

Date: 2026-10-01. Issue #615, item 1 on the battle's refusals. Follows 0113 and 0116 to 0119. The Builder implementing what the Table already agreed (round 184: on-screen text uses display names, scripts keep ids). Chat can argue the wording on the PR.

## What changed

- **Refusals.** Every `ERROR:` line the battle console prints, the protocol's `error.message`, and the client's status after a refused command or art read as a reader sees them: `ERROR: Alder Fenn cannot attack Brigand from 1,8`, `ERROR: Wren has already moved this phase; forecast from 3,7`, `ERROR: Usage: move <unit> <x,y>`. `UnitNames.Message` does it at the edge: each unit id the battle knows reads as its name, an id quoted as it was typed stays as typed (`No living unit 'nobody'`, `No unit 'soldier-1' in sight at dusk`), any other word is left alone (`field_dressing`, `slots run 1-2`), and each line is in sentence case.
- **Why at the edge.** The resolver's messages stay ids, so the rule tests, the Sim and `--trace` read what they always read, and no rejection path in the AI's probes pays for names. The edge is three places: `PlaySession.Error`, `ProtocolSession.Error`, `ClientSession`'s status.
- **The scripted summary** reads `Rejected 2 of 5 commands:`, each reason the line the console printed.
- **The Canto prompt** reads `Ansgar may Canto up to 2 movement: canto ansgar <x,y|stay>`: the name, then the command with its id. A Canto refused for reach says `his Canto has left` (the cast pronoun), not `its`.
- **The certification line** in `play` reads `Certification trial: Alder Fenn plays as Outrider with ...`.
- **The client's** "the enemy phase is playing" status is in sentence case.
- **Transcripts.** The seven that tests compare and that print a changed line (the canto raid, Sallow 61, the outrider and bulwark trials) were regenerated by running their scripts with the tests' own arguments; the diff is wording only.
